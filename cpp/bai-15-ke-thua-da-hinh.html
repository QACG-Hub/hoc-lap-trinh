Kế thừa public

Lớp Dog kế thừa lớp Animal chỉ bằng một dòng khai báo có dấu :. Chó vẫn ăn như động vật (thừa hưởng), nhưng biết sủa riêng (tính năng của lớp con):

kethua.cpp 
#include <iostream>
#include <string>
using namespace std;

class Animal {
public:
    string ten;
    void an() { cout << ten << " dang an" << endl; }
};
class Dog : public Animal {
public:
    void sua() { cout << ten << " go: Gau gau!" << endl; }
};

int main() {
    Dog d;
    d.ten = "Milu";   // thuộc tính thừa hưởng từ Animal
    d.an();           // phương thức thừa hưởng từ Animal
    d.sua();          // phương thức riêng của Dog
    return 0;
}

Milu dang an
Milu go: Gau gau!

virtual & ghi đè

Chuyện gì xảy ra khi lớp con viết lại cùng tên, cùng tham số một phương thức của lớp cha? Đó là ghi đè (override). Để phép thuật đa hình hoạt động, phương thức ở lớp cha phải được đánh dấu virtual, còn lớp con thêm nhãn override để compiler kiểm tra giúp:

virtual.cpp 
#include <iostream>
#include <string>
using namespace std;

class Animal {
public:
    string ten;
    virtual void speak() { cout << ten << " phat ra am thanh..." << endl; }
};
class Dog : public Animal {
public:
    void speak() override { cout << ten << " sua: Gau gau!" << endl; }
};
void choNoi(Animal& a) { a.speak(); }   // một hàm, nhận mọi lớp con

int main() {
    Animal a;
    a.ten = "Bo";
    Dog d;
    d.ten = "Milu";
    choNoi(a);   // chạy phiên bản Animal
    choNoi(d);   // chạy phiên bản Dog — đa hình!
    return 0;
}
▸ KẾT QUẢ 
Bo phat ra am thanh...
Milu sua: Gau gau!

Ngược lại, nếu quên virtual ở lớp cha, chương trình vẫn biên dịch trôi chảy — nhưng chạy sai ý bạn. Xem "tai nạn" kinh điển này:

khong-virtual.cpp 
#include <iostream>
using namespace std;

class Animal {
public:
    void speak() { cout << "Am thanh dong vat" << endl; }   // THIẾU virtual!
};
class Dog : public Animal {
public:
    void speak() { cout << "Gau gau!" << endl; }
};

int main() {
    Animal* a = new Dog();
    a->speak();   // gọi theo kiểu con trỏ Animal → không đa hình
    delete a;
    return 0;
}
▸ KẾT QUẢ 
Am thanh dong vat
// CẢNH BÁO

Khi gọi phương thức qua con trỏ (hoặc tham chiếu) lớp cha, nếu phương thức thiếu virtual, C++ quyết định gọi phiên bản nào theo kiểu của con trỏ (Animal) — nên chú chó Milu lại "kêu" bằng âm thanh chung chung. Thêm virtual ở lớp cha và override ở lớp con thì C++ mới quyết định theo kiểu thật của object (Dog). Đây là cái bẫy im lặng nhất của OOP!

Đa hình với con trỏ

Sức mạnh thật sự của đa hình lộ ra khi bạn dùng con trỏ lớp cha để trỏ tới object lớp con. Một biến Animal* có thể "cầm" bất kỳ con vật nào, và lời gọi a->speak() luôn chạy đúng phiên bản của object thật:

dahinh.cpp 
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void speak() { cout << "Am thanh dong vat" << endl; }
    virtual ~Animal() {}                       // để delete gọi đúng destructor
};
class Dog : public Animal {
public:
    void speak() override { cout << "Gau gau!" << endl; }
};

int main() {
    Animal* a = new Dog();   // con trỏ lớp cha → object lớp con
    a->speak();              // dấu -> thay cho dấu chấm khi dùng con trỏ
    delete a;                // dọn bộ nhớ, destructor của Dog được gọi
    return 0;
}
▸ KẾT QUẢ 
Gau gau!
// GHI NHỚ

Với con trỏ, thành viên truy cập bằng -> thay vì dấu chấm: a->speak(), a->ten. Dòng virtual ~Animal() {} ở lớp cha giúp delete a; gọi đúng cả destructor của Dog — bài học vỡ lòng khi dùng new với kế thừa.

TỔNG KẾT BÀI 15

  • Kế thừa: class Dog : public Animal { }; — lớp con thừa hưởng thuộc tính và phương thức public của lớp cha.
  • Lớp con thêm được thành viên riêng; thành viên private của lớp cha thì không truy cập được.
  • Ghi đè = lớp con viết lại phương thức cùng tên, cùng tham số; lớp cha cần virtual, lớp con nên thêm override.
  • Thiếu virtual, lời gọi qua con trỏ/tham chiếu lớp cha sẽ chạy phiên bản của lớp cha — không đa hình.
  • Con trỏ lớp cha trỏ object lớp con: Animal* a = new Dog(); — gọi bằng a->speak(), dọn bằng delete a;.
  • Đa hình: một lời gọi — nhiều hành vi tuỳ object thật sự; nên khai báo virtual ~Animal() nếu lớp cha có destructor.
