Hàm (function)

[ NHIỆM VỤ #06 ] Chương 3 — Hàm & mảng Mức độ: Chiến binh

Khi chương trình lớn dần, viết tất cả vào main() sẽ thành "mì gói" — rối và khó sửa. Hàm cho bạn đóng gói từng đoạn code thành một "cỗ máy" nhỏ: đặt tên, cho nó nhận đầu vào và trả về kết quả. Viết một lần, gọi dùng mãi. Bắt đầu chương 3 thôi! ⚙️

Hàm là gì?

Hàm giống như một công thức nấu ăn được cất riêng trong tủ: bạn đặt tên cho nó, và mỗi lần gọi tên là máy sẽ chạy đúng các bước trong công thức. Hàm nhận tham số (nguyên liệu) và trả về kết quả (món ăn):

ham-cong.cpp 
#include <iostream>
using namespace std;

int cong(int a, int b) {
    return a + b;
}

int main() {
    int kq = cong(3, 5);
    cout << "3 + 5 = " << kq << endl;
    cout << "10 + 20 = " << cong(10, 20) << endl;
    return 0;
}
▸ KẾT QUẢ 
3 + 5 = 8
10 + 20 = 30

Một hàm không bắt buộc phải trả về gì cả — khi đó dùng kiểu void. Nó chỉ "làm việc" rồi kết thúc, ví dụ in ra màn hình:

ham-void.cpp 
#include <iostream>
using namespace std;

void inChao() {
    cout << "Xin chào, chiến binh!" << endl;
}

int binhPhuong(int x) {
    return x * x;
}

int main() {
    inChao();
    cout << "4^2 = " << binhPhuong(4) << endl;
    return 0;
}
▸ KẾT QUẢ 
Xin chào, chiến binh!
4^2 = 16

Giải phẫu một hàm hoàn chỉnh — nhìn kỹ vì mọi hàm trong C++ đều theo khuôn này:

int cong(int a, int b) { return a + b; }

Hàm phải được viết trước nơi gọi nó. Trong các ví dụ, hàm luôn đặt phía trên main() — gọi hàm chưa biết mặt sẽ bị compiler phàn nàn ngay. Hàm main() mà bạn dùng từ bài 2 cũng chính là một hàm đặc biệt: máy tự gọi nó khi chương trình khởi động.

Tham số & return

Một hàm có thể nhận nhiều tham số và trả về một giá trị. Kết quả trả về có thể dùng ngay như một giá trị bình thường: gán vào biến, in ra, hoặc đưa vào hàm khác. Xem hai "cỗ máy" tính toán:

tham-so-return.cpp 
#include <iostream>
using namespace std;

int binhPhuong(int x) {
    return x * x;
}

int giaiThua(int n) {
    int kq = 1;
    for (int i = 1; i <= n; i++) {
        kq *= i;
    }
    return kq;
}

int main() {
    cout << "5^2 = " << binhPhuong(5) << endl;
    cout << "5! = " << giaiThua(5) << endl;
    cout << "3! = " << giaiThua(3) << endl;
    return 0;
}
▸ KẾT QUẢ 
5^2 = 25
5! = 120
3! = 6

Hàm giaiThua kết hợp cả vòng lặp for lẫn biến tích luỹ — gọi giaiThua(5) là máy tự tính 1 × 2 × 3 × 4 × 5. Giải phẫu lệnh return — "cửa ra" của hàm:

🔬 GIẢI PHẪU CÚ PHÁP
return x * x;
Thành phầnÝ nghĩaBắt buộc
returntừ khoá trả kết quả về nơi gọi hàm✅ (hàm khác void)
x * xbiểu thức được tính rồi trả về — có thể là biến, phép tính, hay giá trị✅
;kết thúc câu lệnh✅
// GHI NHỚ

return kết thúc hàm ngay lập tức — mọi câu lệnh nằm sau nó trong cùng hàm sẽ không bao giờ chạy. Hàm void cũng có thể dùng return; (không kèm giá trị) để thoát sớm nếu cần.

Truyền tham chiếu (&)

Mặc định, C++ truyền bản sao của tham số vào hàm (truyền giá trị). Hàm sửa bản sao thoải mái mà biến gốc vẫn nguyên vẹn. Muốn hàm sửa được chính biến gốc, ta thêm dấu & trước tên tham số — gọi là truyền tham chiếu:

tham-chieu.cpp 
#include <iostream>
using namespace std;

void tang(int x) {          // truyền giá trị — chỉ sửa bản sao
    x = x + 1;
}

void tangThat(int &x) {     // truyền tham chiếu — sửa bản gốc
    x = x + 1;
}

int main() {
    int a = 5;
    tang(a);
    cout << "Sau tang(a): " << a << endl;
    tangThat(a);
    cout << "Sau tangThat(a): " << a << endl;
    return 0;
}
▸ KẾT QUẢ 
Sau tang(a): 5
Sau tangThat(a): 6

tang(a) nhận bản sao nên a vẫn là 5. tangThat(a) dùng chung với biến gốc nên a thành 6. Giải phẫu dấu & quyền lực này:

🔬 GIẢI PHẪU CÚ PHÁP
void doiGiaTri(int &x) { x = 10; }
Thành phầnÝ nghĩaBắt buộc
voidhàm không trả về giá trị — chỉ thay đổi dữ liệu nhận vào✅
int xtruyền giá trị — hàm làm việc trên bản saomột trong hai cách
int &xtruyền tham chiếu — dấu & nghĩa là "dùng chung" với biến gốcmột trong hai cách
x = 10;gán trong thân hàm — với tham chiếu, biến gốc đổi theo thành 10✅
// CẢNH BÁO

Quên dấu & là lỗi "thầm lặng" hay gặp nhất khi viết hàm thay đổi giá trị: chương trình vẫn biên dịch, vẫn chạy, nhưng biến gốc không hề đổi vì hàm chỉ sửa bản sao. Nếu hàm của bạn "không có tác dụng kỳ lạ", hãy kiểm tra ngay dấu & trong danh sách tham số. Ngược lại, khi chỉ cần đọc dữ liệu, cứ truyền giá trị bình thường để an toàn.

TỔNG KẾT BÀI 06

  • Hàm đóng gói code thành khối tái sử dụng: kiểu_trả_về tên_hàm(danh_sách_tham_số) { ... }.
  • Hàm phải được viết trước nơi gọi; main() cũng là một hàm đặc biệt.
  • return trả giá trị về nơi gọi và kết thúc hàm ngay lập tức; hàm không trả về dùng kiểu void.
  • Tham số là "nguyên liệu" đầu vào, đặt trong ngoặc đơn; nhiều tham số ngăn cách bởi dấu phẩy.
  • Truyền giá trị: hàm sửa bản sao, biến gốc không đổi. Truyền tham chiếu int &x: hàm sửa được biến gốc.
  • Quên dấu & là nguyên nhân số một khiến hàm "sửa mãi mà biến không đổi".
